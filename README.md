# Casual-Music

> 一款完整运行在浏览器里的音乐制作工作站。

> `Casual-Music` 是本项目的正式名称，仓库标识为 `casual-music`。

**当前状态：需求与架构阶段。** 仓库中目前只有产品、功能与架构规格文档，还没有可运行的构建产物。

---

## 1. 为什么做这个

现有的浏览器音乐工具大多刻意做减法：几个循环素材、少量合成器、固定预设，工作流止步于"快速出个想法"。用来记灵感够用，但替代不了真正的制作环境。

Casual-Music 走的是相反的方向：**一个具备桌面级密度的浏览器 DAW**。和专业工作站一致的工作流支柱——通道机架、步进音序器、钢琴卷帘、编排时间线、混音器、自动化——加上足够大的内置乐器与效果器库、真实的工程文件、真实的导出能力，以及零安装。

设计原则：**先把创作主链路做完整，再横向扩展生态。** 用户应当能在不离开浏览器的前提下，从空工程走到一首完成的曲子。

## 2. 它包含什么

### 核心工作流

| 模块 | 能力 |
|---|---|
| 走带 | 播放/暂停/停止、歌曲与样式两种模式、BPM 含点按/半速/微调、拍号与摇摆、节拍器、预备拍、插入录音、循环区间 |
| 通道机架 | 增删与重排通道、单通道音量/声像/静音/独奏、路由、分组与筛选、叠加、通道设置 |
| 步进音序器 | 单样式最多 512 步、逐步力度与音高、摇摆、与钢琴卷帘数据互通 |
| 钢琴卷帘 | 音符创建/移动/缩放/切割/粘合、力度、声像、释放、滑音、幽灵音符、音符分组、量化、人性化、吸附音阶、和弦印章、事件编辑器 |
| 编排 | 样式剪辑、音频剪辑、自动化剪辑上时间线，最多 500 轨，多编排页、演出模式、剪辑增益/淡入淡出/切割、标记与循环区域 |
| 混音器 | 500 条插入轨 + 当前轨 + 主轨、每轨 10 个效果槽、发送、侧链、插件延迟补偿、EQ/相位/立体声/推子、电平表 |
| 自动化 | 曲线与步进两种自动化剪辑、事件自动化、包络/LFO/峰值/XY/键盘控制器、参数链接、宏、自动化录制与平滑 |
| 浏览器 | 工程内容、采样、预设、插件库、搜索、试听、标签、收藏、丢失文件重链 |
| 录音 | 音频输入录音与监听、MIDI 录制与叠加、多版本录制管理、内置音频编辑器 |
| 导出 | WAV 16/24/32 位、FLAC、MP3、分轨导出、尾巴处理、LUFS 计量、MIDI 文件导出 |

### 乐器

- **54 个乐器插件**，覆盖完整桌面 DAW 的全部乐器门类：减法合成、FM、加法/重合成、物理建模、采样器、鼓机、切片器、颗粒、波表、共振峰/语音、模块化、音色库、独奏原声、合奏、芯片音、电影质感。
- **100+ 个乐器定义**建立在 **18 个共享 DSP 引擎家族**之上，新增乐器等于一份参数模式加一份采样映射，而不是重写引擎。
- **General MIDI 128 个音色全部可发声**，每个音色都配置了合成兜底，不会出现"点了没声音"。
- **60+ 套鼓组**，覆盖原声、电子（808/909/707/CR-78/LinnDrum/DMX）、混合、管弦打击、世界打击。
- 完整的管弦与民族覆盖：弦乐、铜管、木管、人声与合唱、吉他弹拨、键盘、键盘打击、以及各地域乐器。

### 效果器

**93 个效果器**，分七组：EQ 与滤波、动态、延迟与时间、混响、调制与空间、失真与饱和、工具与分析。旗舰规格包括 8 段参数 EQ、带前瞻的砖墙限制器、高质量算法混响、卷积混响、多段最大化、时间弯曲引擎、声码器、模块化容器。

每个效果器都支持参数自动化、预设、干湿比、旁通、延迟上报（用于延迟补偿），以及在适用情况下的立体声与侧链操作。

## 3. 技术方案

| 决策点 | 选择 | 理由 |
|---|---|---|
| 音频内核 | 单一的 AudioWorklet DSP 图，而不是成千上万个 Web Audio 原生节点 | 采样级精确调度、离线与实时渲染一致、CPU 可控、自动化与延迟补偿可掌控 |
| DSP 语言 | 以 TypeScript 为主，重型模块用 Rust/WebAssembly | 该快的地方快迭代，该省的地方省算力 |
| UI | React + Canvas2D，时间线与钢琴卷帘自绘并虚拟化 | 500 轨、上万音符下稳定 60fps |
| 状态 | Zustand + Immer + 命令总线，撤销由逆命令构成 | 复杂编辑行为可预测，并为协作编辑留好通道 |
| 工程格式 | ZIP 容器 + JSON 清单 + 素材（自有 `.flw` 格式） | 可版本化、可移植、可 diff、可协作 |
| 存储 | 本地优先，IndexedDB 与 OPFS，云同步后续再加 | 早期阶段没有后端成本与隐私暴露 |
| 协作 | Yjs CRDT，复用同一份文档模型 | 对象级合并，而不是整文件锁 |

### 性能目标

| 指标 | 目标 |
|---|---|
| 端到端延迟 | 48 kHz / 128 帧缓冲下 ≤ 30 ms |
| 稳定性 | 连续播放 30 分钟无中断 |
| CPU | 中端笔记本上 64 复音 + 16 轨 + 8 效果器不超过单核 60% |
| UI | 500 轨、10000 音符、1000 剪辑下 55–60fps |
| 冷启动 | 到可播放状态 ≤ 3 s（不含采样解码） |
| 工程加载 | 50 MB 工程 ≤ 3 s |
| 导出 | 至少 2 倍速于实时，可取消，有可见进度 |

### 浏览器支持

Chrome 与 Edge 为主目标；Firefox 支持；Safari 17+ 支持但有明确记录的降级项。AudioWorklet 是硬性要求。

## 5. 1.0 的非目标

- 托管原生 VST/AU 二进制（浏览器沙箱内不可能实现，长期答案是基于 WebAssembly 的插件协议）
- 底层音频驱动与跨应用音频桥接
- 与任何现有商业 DAW 在像素级一致的界面、图标或皮肤
- 对封闭专有工程格式做 100% 双向导入
- 厂商账号体系与第一方云端采样订阅

## 7. 原则

1. **只用自有资产。** 不使用任何第三方商标、图标、出厂预设或捆绑采样。乐器与效果器使用自有命名与自有声音设计。
2. **授权可追溯。** 每个采样记录来源、许可、作者与哈希。只用 CC0 与 CC BY 素材，绝不使用非商业或禁止演绎素材。每套素材包可独立移除，工程降级为"重链丢失文件"流程。
3. **默认本地优先。** 除非用户显式开启同步，音频与工程数据只留在本机。
4. **诚实划定范围。** 浏览器做不到的能力写进非目标，而不是悄悄降级。
5. **可访问性不是可选项。** 核心流程可全键盘完成，对比度满足 WCAG AA，200% 缩放不裁切。
